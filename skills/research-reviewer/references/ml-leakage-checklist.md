# Empirical Data Science & Machine Learning Leakage Audit Checklist

Data leakage is the single most common cause of artificially inflated performance metrics in empirical research. When a method achieves suspiciously high performance ($R^2 > 0.98$, accuracy/AUC $> 95\%$, or massive unexplained gains), the reviewer must systematically audit for the following eight leakage vectors across tabular, time-series, text, vision, and systems studies.

---

## 1. Entity & Subject-Level Leakage (Identity Contamination)

In datasets containing multiple observations from the same individual, entity, or source (clinical patients, web users, bank clients, schools, IoT sensors, mobile devices):

### The Red Flags
- Reporting an unstratified row-level random split (e.g. `train_test_split(df, test_size=0.2)`).
- The dataset description omits grouping identifiers (`patient_id`, `user_id`, `school_id`, `device_id`).

### The Mechanism
Models easily memorize entity-specific idiosyncrasies (unique user behavioral patterns, anatomical vascular trees, client device noise) rather than true generalizable relationships. When records from the same entity appear in both train and test splits, evaluation measures entity recognition rather than generalization.

### The Audit Test
```python
# Zero intersection check across entities
train_entities = set(train_df["entity_id"])
test_entities = set(test_df["entity_id"])
leakage = train_entities.intersection(test_entities)
assert len(leakage) == 0, f"Critical Leakage: {len(leakage)} entities appear in both train and test sets!"
```

### Remediation
- Enforce `GroupKFold` or `StratifiedGroupKFold` on the grouping entity ID.
- If grouping keys are unavailable in a legacy dataset, explicitly acknowledge entity-level grouping as a major limitation in the manuscript.

## 2. Target & Outcome Bleed (Tabular / Relational Proxy Features)

In tabular data science, predictive maintenance, economics, fraud detection, and churn analysis:

### The Red Flags
- One or two features dominate feature importance ($> 80\%$ gain).
- Features collected downstream from the event or generated by the same logging pipeline as the label.

### The Mechanism
A feature directly or indirectly encodes the outcome variable. For example:
- Including `account_cancellation_date` or `refund_amount` to predict churn.
- Including a post-diagnosis medication code to predict disease presence.
- Retaining an internal database surrogate key correlated with the label.

### Remediation
- Conduct temporal feature lineage audits: verify that all feature values were definitively recorded **before** the decision or event point.
- Drop proxy columns and test whether model performance collapses to realistic bounds.

---

## 3. Temporal & Lookahead Bias (Time Series & Sequential Data)

In financial forecasting, sensor telemetry, energy demand, server metrics, and sequential text:

### The Red Flags
- Randomly shuffling time-stamped records into $k$-fold cross-validation.
- Computing rolling averages or exponential smoothing using centered windows (`center=True`) that incorporate future data points.

### The Mechanism
When future observations are present in the training set to predict past test events, models exploit future trend signals that would never exist at deployment time.

### Remediation
- Enforce forward-chaining or expanding window validation (`TimeSeriesSplit` or walk-forward validation).
- Ensure strict out-of-time (OOT) test sets where `max(train_timestamp) < min(test_timestamp)`.

---

## 4. Preprocessing & Feature Selection Leakage

### The Red Flags
- Applying dataset-wide standardization (`StandardScaler`, `MinMaxScaler`) across the combined dataset before splitting.
- Selecting top-$k$ correlated features or running PCA across all data prior to $k$-fold cross-validation.
- Imputing missing values using global dataset means or medians before partitioning.
- Applying data augmentation (SMOTE, image rotations, synonym replacement) before splitting.

### The Mechanism
Selecting features or fitting scalers on the full dataset leaks information about the distribution and label relationships of the validation/test folds into the training phase, yielding heavily over-optimistic performance estimates.

### Remediation
- Use encapsulation pipelines (e.g. Scikit-Learn `Pipeline` or `ColumnTransformer`).
- All transformers, scalers, imputers, and feature selectors must be fitted **strictly on the Train split**, then used to `.transform()` the Test split.
- Apply resampling and augmentation exclusively within the training fold.

---

## 5. Test Set & Benchmark Contamination

In NLP, large language models, code generation, and standard benchmark evaluation:

### The Red Flags
- Pretrained foundation models evaluated on public benchmarks (MMLU, GSM8k, HumanEval) without decontamination audits.
- Checkpoints selected by repeatedly probing the final test set.
- Decision thresholds tuned directly on test set ROC curves.

### The Mechanism
When benchmark items exist in the massive web scraping corpora used for pretraining, the model simply memorizes benchmark solutions rather than exhibiting genuine problem-solving.

### Remediation
- Execute rigorous $n$-gram and embedding decontamination checks between training corpora and evaluation benchmarks.
- Maintain a strict 3-way split: **Train**, **Validation** (for early stopping and threshold tuning), and **Test** (evaluated strictly once at manuscript completion).

---

## 6. Metric Gaming on Skewed & Imbalanced Outcomes

### The Red Flags
- Reporting raw accuracy on datasets with high class imbalance (e.g. *"achieves 98.5% accuracy"* when 98% of samples are negative).
- Reporting only micro-averaged metrics that hide total failure on rare critical classes.
- Regression studies reporting only $R^2$ while ignoring outliers or MAE on skewed targets.

### The Mechanism
A trivial constant predictor achieves 98% accuracy on a 98:2 class imbalance while offering zero operational or scientific utility.

### The Audit Test
Demand:
1. Macro-averaged F1-Score (unweighted mean across all classes).
2. Area Under the Precision-Recall Curve (PR-AUC) for the minority class.
3. Confusion matrices with explicit counts of True Positives, False Positives, and False Negatives.
4. Balanced Accuracy, Cohen's Kappa ($\kappa$), or Matthew's Correlation Coefficient (MCC).

---

## 7. Confounder, Site, and Instrumentation Leakage

### The Red Flags
- Data collected across multiple laboratories, hospitals, sensor models, or server hardware configurations.
- Condition A samples collected predominantly on Instrument 1, while Condition B samples collected on Instrument 2.

### The Mechanism
Models readily learn instrument-specific sensor noise, batch effects, compiler flags, camera border geometry, or background artifacts rather than the underlying scientific phenomenon.

### Remediation
- Out-of-domain / cross-center validation: train on Site A data, test strictly on Site B data.
- Analyze feature attributions or saliency maps to verify that decisions rely on domain-meaningful variables rather than instrument artifacts.

---

## 8. Duplicate & Near-Duplicate Contamination

### The Red Flags
- Datasets gathered from web scraping, composite public repositories, or synthetic data expansion.
- Datasets containing near-identical prompts, duplicate logs, or identical image crops.

### The Audit Test
- Run exact hash deduplication (MD5/SHA256) and fuzzy deduplication (MinHash for text, perceptual hash for images).
- Verify that duplicates are eliminated before the data split is formed.
